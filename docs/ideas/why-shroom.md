# Why “Shroom” Works

**Shroom** is short, memorable, and naturally connected to the project’s core idea: a shared, isolated room that coding agents can enter and work inside.

The name carries several useful readings at once. It can suggest **shell + room**, matching the SSH-first design; **shared + room**, matching the idea that multiple coding agents can use the same persistent workspace; and even loosely **SSH + room**, since SSH is the primary way agents enter the workspace. None of these needs to be formalized as an acronym—the associations are enough.

It also fits the architecture itself. A Shroom workspace exists independently of whichever agent is currently attached to it: agents can enter, work, leave, and hand the same environment to another agent. That makes “room” a stronger metaphor than “sandbox” for the user-facing concept.

As a brand, **Shroom** is more distinctive than literal names such as *Workroom*, *Shellroom*, or *Agentroom*. It sounds like a real standalone product name while still preserving the “room” idea underneath. The mushroom association adds some playfulness without requiring the interface or terminology to adopt a mushroom theme.

The name also leaves room for straightforward product language. The software can simply be **Shroom**, while its concepts remain ordinary terms such as **workspace**, **attachment**, and **SSH connection**.

A concise positioning line is:

> **Shroom — shared, isolated workspaces for coding agents.**
